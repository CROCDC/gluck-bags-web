Relevamiento SEO exhaustivo de gluckbags.com (storefront Flask server-rendered, detrás de Cloudflare). Motor determinístico + fan-out multiagente con verificación adversarial de cada hallazgo contra el sitio vivo. Lo positivo: Lighthouse SEO 100 y Performance 94, CLS 0, TBT 10 ms, sin interstitials intrusivos, HTML rastreable sin brecha JS, un solo idioma (es-AR, sin hreflang necesario). Pero el sitio tiene un problema CRÍTICO que Lighthouse no detecta: el canonical y los datos sociales de TODO el dominio apuntan a un dominio gemelo vivo (gluck.nexttech.com.ar), así que la marca le cede su indexación al alias. Resuelto eso (un cambio de config SITE_URL), siguen: duplicación de host sin redirección, falta de sitemap, ausencia total de datos estructurados, sin páginas de confianza (E-E-A-T) y fichas de producto delgadas. Alcance: muestra representativa de tipos de página (home, 3 PDP, variantes con parámetros, 404), no el catálogo completo; los hallazgos por-URL valen como patrón. Backlinks/autoridad off-page y volumen real de indexación quedan fuera (requieren Ahrefs/GSC).

#01 Crítico

Canonical cross-dominio: gluckbags.com cede toda su autoridad a un dominio gemelo vivo (gluck.nexttech.com.ar)

PENDIENTE
Canonical / Indexaciónurl-canonicalizationTodo el sitio (home + todas las PDP + variantes de URL)

Cada página de gluckbags.com declara como canónica una URL de OTRO dominio: gluck.nexttech.com.ar. Ese segundo dominio está VIVO, sirve contenido idéntico y se auto-canonicaliza. Resultado: gluckbags.com le dice a Google «la versión buena de esta página vive en gluck.nexttech.com.ar», así que Google indexa y rankea el alias y trata al dominio de marca como un duplicado que apunta hacia afuera. El dominio de marca puede quedar directamente fuera del índice bajo su propio nombre.

Prueba técnica
Verificado en vivo (curl UA Chrome, HTTP 200, sin captcha):

# gluckbags.com/  (dominio de marca)
<link rel="canonical" href="https://gluck.nexttech.com.ar/">
<meta property="og:url"   content="https://gluck.nexttech.com.ar/">
<meta property="og:image" content="https://gluck.nexttech.com.ar/static/img/og-image.jpg">

# gluck.nexttech.com.ar/  (el gemelo) -> HTTP 200, mismo <title> 'GLÜCK · Bolsos minimalistas...'
<link rel="canonical" href="https://gluck.nexttech.com.ar/">   # se auto-canonicaliza

Causa raíz: el config de producción SITE_URL/site_url está apuntado al alias de staging. La home emite el canonical desde site_url (app/templates/index.html:23) y og:url/og:image están hardcodeados al alias en base_public.html y product_detail.html.
G gluck.nexttech.com.ar
GLÜCK · Bolsos minimalistas de cuero vegano
GLÜCK — Bolsos minimalistas de cuero vegano. Carteras y bolsos de cuero vegano, hechos a mano con un diseño minimalista y atemporal.

Recomendación: 1) Setear en producción SITE_URL=https://gluckbags.com y corregir los og:url/og:image hardcodeados en base_public.html y product_detail.html. 2) Redirigir 301 todo gluck.nexttech.com.ar -> https://gluckbags.com (o, si debe seguir vivo, ponerlo noindex y canonical hacia gluckbags.com). 3) Verificar el dominio en Google Search Console y pedir reindexación. Es el arreglo de mayor impacto y debe ir primero.

#02 Alto

#16 Info

robots.txt: bloqueo de crawlers de IA (intencional, Cloudflare) — el rastreo de buscadores está permitido

INFO
Crawl / robots.txtindexability-crawlrobots.txt

Nota de transparencia + corrección. El pase determinístico marcó «robots.txt bloquea todo el sitio (Disallow: /)» como CRÍTICO: es un FALSO POSITIVO. El Disallow: / está acotado a bots de IA nombrados (Amazonbot, GPTBot, ClaudeBot, Google-Extended, etc.), cada uno bajo su propio User-agent. Para User-agent: * la directiva es Allow: /. Googlebot y el rastreo de búsqueda están permitidos.

Prueba técnica
robots.txt (gestionado por Cloudflare):

User-agent: *
Content-Signal: search=yes,ai-train=no
Allow: /

User-agent: GPTBot
Disallow: /
User-agent: ClaudeBot
Disallow: /
User-agent: Google-Extended
Disallow: /
... (resto de bots de IA)

User-agent: *
Allow: /

Recomendación: No requiere acción salvo que se desee permitir el entrenamiento de IA. Es un ajuste deliberado de Cloudflare; el SEO de búsqueda no se ve afectado. Se incluye sólo para descartar el falso positivo.
